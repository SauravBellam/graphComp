# Plan A script fixes (Oct 11, 2026)

Follow-up to `ANALYSIS_2026-10-11.md`. Three numbers in the Oct 10 run could not be quoted as they stood: static reachability for H-A2 (no BFS source for most tasks), the fail-to-pass basis (291 "pre-passed" tests), and two unexplained data gaps (requests "missing" 20% of its sync functions; 43 to 139 `provided_only` nodes per v2 graph). This note records what was wrong in the scripts, what changed, how to rerun, and what a local re-analysis of the existing traces already shows. Paths are relative to `planA_results/`. Anything not read directly from a file is tagged **[inferred]**.

## 1. What the diagnosis found

### 1.1 The two data gaps are one id-scheme difference

Read from the v2 graphs on disk (`vm-a2/results/a6/graphs_v2/`), which carry file and line numbers for every parsed def plus the `provided_only` nodes:

- **Nested definitions are nodes in the provided graph.** They appear under a flattened id: enclosing *functions* and the `<locals>` marker are dropped, classes are kept. `requests.auth.HTTPDigestAuth.build_digest_header.<locals>.md5_utf8` is the node `requests.auth.HTTPDigestAuth.md5_utf8`; a class defined inside a test function keeps its methods, so `tests.test_pretty.Thing._repr_html_` is a node. In the first fastapi graph checked, 52 of 52 `provided_only` nodes are explained this way (44 one level deep, 8 two levels); in the first rich graph 107 of 107. The old scripts built nested ids with `<locals>`, so A1 reported 0 of 26,857 nested defs present and A2 attributed 2,909 dynamic edges to `absent_nested`. Both are artefacts.
- **requests additionally lists a subset of `TestRequests` methods at module level.** In `requests_0b401c76…`, 76 of 183 `TestRequests` methods exist only as `tests.test_requests.<name>`, with no class segment; the class node itself and the other 107 methods are normal. These 76 are exactly the functions A1 counted as absent (1,317 of 1,425 absent requests functions are in `tests/test_requests.py`, the rest in `tests/test_utils.py`; `vm-main/results/a1/a1_async_audit.csv.gz`). No syntactic rule separates the two groups: the flattened ones are not contiguous, not the ones with nested defs, not the decorated ones, and not the ones after the first nested def (`prev_has_nested × flattened` = 15/22 vs 61/84). **[inferred]** this is a generator bug; the new A7 script records enough per-method features to look for the rule against the real snapshot.
- The `provided_only` residue after the nested rule, 23 to 25 nodes per requests graph, is the same class-dropped-method population plus a handful I could not classify from the v2 files; A7 classifies them against the source.

### 1.2 Static reachability (H-A2) had no source

`a2/analyze.py` seeded the BFS from the fail-to-pass test's own node, falling back to its class or module. The provided graph has no module nodes and 124 of 129 tasks derive their fail-to-pass tests from `test_patch`, so the test is new and absent from the base graph: 78 of 90 usable tasks had an empty source set (`a2_tasks.csv`, `f2p_source_levels`). "5 of 90 statically reachable" measured source availability, not reachability.

### 1.3 Fail-to-pass basis

`check_f2p` classed a test as `pre_passed` whenever the pre run had no failing record for it, which includes tests that were never collected pre-fix because their module failed to import (for example `fastapi_15030`, 25 expected tests, pre run `error: 2`). It also had no notion of the harness's own criterion, which looks at the post run only.

### 1.4 Entry-point definition had to survive two things

A first "entry = functions the test frame calls directly" definition left 30 usable tasks without sources. Two reasons, both verified on traces: fastapi tests reach the framework only through starlette's `TestClient`, which runs the app in an anyio worker thread, so no ancestor frame is the test; and the true root there is `FastAPI.__call__`, an async def that is not a node, so the first *node* on the path has a non-test caller. The final definition walks caller chains through non-node frames (section 2.2).

## 2. What changed in the scripts

All edits are in `scripts/`; the Oct 10 versions remain in git history and `provenance/scripts_sha256.txt`.

### 2.1 `planA/common.py`

- `flatten_qualname(q)`: the provided graph's id rule for nested defs (drop function scopes and `<locals>`, keep classes). Identity on ids without `<locals>`.
- `provided_node_id(module, qualname)`: `module.flatten_qualname(qualname)`.

### 2.2 `planA/a2/analyze.py`

- `Mapper.map`: a `<locals>` qualname is first tried under its flattened id (`node` or `collapsed_init` when present); `nested` now means absent even when flattened.
- `entry_nodes(...)`: new. The base-graph nodes where a fail-to-pass test enters the library: executed non-test nodes none of whose caller chains in that test (direct or via-library edges, walked through frames that are not nodes) reaches another non-test node before test code. Pre and post traces are both used.
- Reachability is reported from both source sets. Old fields keep their names; new per-gold fields: `entry_sources_defined`, `is_entry`, `static_reachable_from_entry_directed`, `static_hops_from_entry_directed`, `..._undirected`. New per-task fields: `n_entry_sources`, `gold_any_static_reachable_entry`, `gold_all_executed_static_reachable_entry`, `gold_executed_not_static_entry`, `gold_executed_is_entry`, `gold_min_hops_from_entry_directed`. Summary blocks add `tasks_entry_sources_defined`, `tasks_gold_static_reachable_entry`, `tasks_gold_all_executed_reachable_entry`, `tasks_gold_executed_is_entry`, `tasks_gold_reachable_entry_undirected_only`, `gold_min_hops_from_entry_hist`, and `tasks_gold_static_reachable_given_sources` for the old definition.
- `check_f2p`: new status `uncollected_pre` (absent from the pre run, passed post), kept apart from `pre_passed`; `f2p_all_confirmed_or_uncollected`; `harness_all_expected_pass_post` (post run has no failures or errors and every expected test passed, the harness's resolution criterion). `usable` is unchanged. New `strict` flag (usable and every expected test confirmed) and a `strict_tasks` summary block; `coverage.f2p_check` reports all of these.
- Gold node ids from an older A1 run are flattened on the fly if the raw id is not a node.

### 2.3 `planA/a1_census.py`

- Presence is tested under `provided_node_id`; `node_id_locals` is kept as a column. The `nested` presence rate is now meaningful.
- New column `present_under_class_dropped_id` and summary count `present_under_class_dropped_id` per kind: a def whose `module.name` is a node although `module.Class.name` is not (the requests case).
- Gold symbols use the same id, so nested gold symbols become resolvable and A5's gold set changes accordingly.

### 2.4 `planA/a6_release.py`

- Nested defs are emitted under their flattened id with `nested: true` and `qualname`; a nested def whose flattened id collides with an existing def is recorded on that node's `id_collisions` instead of overwriting it. `contains` edges point to the innermost enclosing def.
- `tests` edges from tests added by `test_patch` no longer dangle: the test is added as a `test_function` node with `from_test_patch: true`.
- Summary adds `nested_defs`, `nested_defs_in_provided`, `id_collisions`; `task_profile.csv` adds `a2_static_sources_defined`, `a2_n_entry_sources`, `a2_gold_static_reachable_entry`, `a2_gold_min_hops_from_entry`, `a2_strict`, `a2_harness_resolved_post`.

### 2.5 New: `planA/a7_id_audit.py`

Per graph, parses the snapshot and classifies every provided node (`matched_def`, `matched_nested_flat`, `class_dropped_method`, `package_or_module`, `unmatched` with the text head) and every parsed def (`present`, `present_nested_flat`, `present_class_dropped`, `absent_async`, `absent_nested`, `absent_other`). For class-dropped methods it writes `a7_class_dropped.csv` with line numbers, decorators, body features, the preceding sibling and whether the provided node's text equals the method's source. Shardable; `merge` subcommand. Smoke-tested on the synthetic fixture.

### 2.6 Tests and fixture

`tests/make_fixture.py` now puts the nested function in the provided graph under its flattened id (`mini.core.inner`), as the real generator does. `tests/test_pipeline.py` gains `test_flatten_qualname`, `test_check_f2p_statuses`, `test_entry_nodes`, and assertions on the new A1, A2 and A6 outputs. The full suite (fixture pipeline A1 through A6 with real per-task venvs) passes: 10 passed in 27 s on Python 3.13.16.

### 2.7 New: `ops/rerun_fixes.sh`

Runs, on the VM that holds the archive and `results/a2_runs`: A1 (sharded, merged) into `a1_v2`, A7 into `a7`, A2 analysis on the existing traces into `a2_v2`, A5 into `a5_v2`, A6 into `a6_v2`, then a `scripts_sha256_v2.txt`. No new test runs. The Oct 10 outputs are left in place for comparison.

```
bash ops/rerun_fixes.sh ~/graphComp/archive ~/results ~/cache 8
```

## 3. Local re-analysis of the existing traces

The archive is not in this repository, so I rebuilt stand-in provided graphs from the v2 graphs (nodes with `in_provided_graph` or `provided_only`, edges of type `calls_static`) and ran the new `analyze.py` over the 129 real run folders in `vm-a2/results/a2_runs/` with the Oct 10 `a1_gold_symbols.jsonl`. Two differences from the real archive: the stand-in graphs lack the containment pseudo-edges (`Class -> Class.__init__`) that `analyze.py` strips before edge comparison but that the BFS can traverse, and the gold symbols are the pre-fix A1 ones (flattened on the fly). Treat the numbers below as what the VM rerun should approximately reproduce, not as the result.

Per repo, usable: fastapi 31 of 35 tasks reach a gold node from the entry (27 of 35 reach all); rich 26 of 28 (21 of 28); requests 7 of 7.

What this says about H-A2, pending the VM rerun: the executed gold function is usually reachable in the static graph from where the failing test enters the library. The gap the graph leaves is not reachability but distance and omission: in 39 of 70 tasks the nearest gold node is two or more `calls` hops away (on a graph whose hubs have in-degree above 70), 16 executed gold nodes are reachable only against edge direction, 4 not at all, and the async gold functions are not in the graph to be reached. The 5 usable tasks still without an entry set are rich tasks whose gold node was not executed by the fail-to-pass test, so they do not enter the reachability denominators.

Recall and precision barely move; the nested fix shifts about 850 edges from `absent_nested` to the between-nodes categories, where most of them are misses.

## 4. Other script issues noticed, not changed

Listed so the rerun can be read with them in mind. None changes the headline results; each is a small, contained edit if wanted.

1. **`check_f2p` and skipped tests.** A test skipped pre-fix and passed post-fix is counted `pre_passed`. Rare; a `pre_skipped` status would be cleaner.
2. **Edge attribution uses the pre-fix trace only** (`analyze.py`, by design: the graph is the base commit's). For the 9 collection-error and 2 import-error tasks the pre trace is nearly empty, and their post trace could supply edges not touching patched functions. An opt-in `--edges-from-post-when-pre-missing` would raise coverage from 90 to about 100 tasks at the cost of a few post-fix edges.
3. **`is_test_module_id`** also matches a final symbol named `test_*` or `*_test` (noted in `scripts/REVIEW.md`); a source function with such a name is classed as test code and excluded from the entry set.
4. **`a6_release.py` `contains` edge for a nested def** points to the enclosing def's flattened id; if that id was itself skipped as a collision the edge can dangle. Not observed on the fixture; a one-line guard (`parent if parent in nodes else mod`) would close it.
5. **`a3_encoder.py` samples the first 200 node keys** with non-empty text per graph, not a random sample (line 132). Fine for a 0.07 cosine, but the write-up should say so.
6. **A5 hit rates** exclude the 13 tasks whose gold symbols are all absent; with the flattened ids a few nested gold symbols become hittable, so A5 must be rerun (the launcher does) and the write-up should still report rates over all 129 tasks.
7. **Via-library edges in worker threads.** `trace_plugin.py` walks ancestors within the current thread only, so a repo function first entered inside an anyio worker thread has no via-library caller. `entry_nodes` is robust to this; `recall_agent_facing` on the `any` channel is slightly conservative for fastapi because those cross-thread edges are never recorded.
8. **`Mapper.module` fallback** returns a module with no nodes when its parent package is a prefix of some node. Correct for async-only modules, but it also maps stray scripts under a package directory; the `unmapped_module` count (27 edges) would otherwise be slightly higher. Harmless.
9. **`expected_f2p`** takes every added `def test_*` in `test_patch`, including helpers and tests the patch moves rather than adds. `uncollected_pre` and `pre_passed` now separate the honest cases; a `git diff`-aware matcher would be more precise.
