# Plan A results: analysis of the Oct 10, 2026 run

Written Oct 11, 2026 from the files under `planA_results/`. Scope: what the six steps measured, which Plan A hypotheses the numbers support, and which numbers should not be quoted as they stand. Every claim names the file it comes from. Anything not read directly from a result file is tagged **[inferred]**. Paths are relative to `planA_results/`.

Inputs read in full: `../HANDOFF.md`, `../compPhilosophy.md`, `README.md`, `scripts/REVIEW.md`, every `*_summary.json`, the task-level CSVs, the A2 logs, and the scripts where a metric's definition mattered.

## 1. Key findings

1. **The provided graph has no async functions and no nested functions, in every one of the 127 graphs.** 0 of 45,492 async defs are nodes (0 of 28,113 in source files); 0 of 26,857 nested defs. Sync functions in source files are 100% present, classes 98.0% (`vm-main/results/a1/a1_summary.json`, `omission_direct_*`). This confirms handoff finding 5.1 across all graphs.

2. **The omission lands on the code that needs fixing.** 81 of 711 gold-patch symbols are async; 0 are nodes. 22 of 129 tasks (17.1%) have at least one async gold symbol, 21 of them fastapi (31.3% of fastapi tasks). Overall 463 of 711 gold symbols (65.1%, CI 61.5 to 68.5) exist as nodes. Six tasks have no gold symbol in the graph at all (4 fastapi async, 2 rich nested) (`a1_summary.json`; `a1_tasks.csv`).

3. **The harness's name resolver converts omissions into wrong answers rather than "not found".** A bare-name query for an absent async def silently resolves to some other node 65.4% of the time (36,924 of 56,487), 26,851 of those to a test node. Even for a function that is present, a bare-name query returns a different same-named node 41.2% of the time (fastapi 46.6%, httpx 62.0%), and 47.9% for classes. 26 tasks (20.2%) have a gold symbol whose harness-style query returns a wrong node (`a1_summary.json`, `misresolution`, `task_rates`). The resolver copy is a line-for-line mirror of swegemma 0.2.7 (`scripts/planA/common.py`, `scripts/REVIEW.md`).

4. **Against execution, the `calls` edges are low-recall and, within executed code, low-precision.** On the 90 usable tasks, recall over edges the graph could represent is 38.0% (7,664 of 20,174; CI 35.6 to 41.3), and 30.3% counting edges to absent defs. Observed precision, static edges whose endpoints both ran and that were seen at runtime, is 21.1% (7,664 of 36,268; CI 19.7 to 22.4) (`vm-a2/results/a2/a2_summary.json`, `usable_tasks`). Recall is highest in fastapi (67.6%) and lowest in rich (30.3%); precision is 16.5% in fastapi, 22.6% in rich, 34.6% in requests (`per_repo_usable`). H-A1 predicted "high precision, low recall" and "lowest recall in fastapi"; both halves are contradicted on these numbers, with the caveats in section 4.

5. **The embeddings are not EmbeddingGemma output, and their nearest neighbours are mostly tests.** The best re-embedding candidate reaches mean cosine 0.073 with the provided vectors (embeddinggemma-300m, name variant); embeddinggemma-2 reaches 0.015; the MiniLM control 0.036. No candidate is identified (`vm-a2/results/a3/a3_summary.json`, `vm-a2/results/a3_gemma2/a3_summary.json`). Among a node's 10 nearest neighbours by cosine, call neighbours are 2.0% in fastapi and 2.8% in rich, while test nodes are 67.3% in fastapi, 60.6% in requests and 44.8% in rich (`vm-main/results/a4/a4_knn.csv`, repo means).

6. **The harness's retrieval mode loses to plain BM25 on file hit rate, and the cosine step adds almost nothing.** On the 116 tasks with at least one gold node, gold-file Hit@5 is 34.5% for harness mode versus 51.7% for BM25 over node text (27 tasks BM25-only, 7 harness-only, exact McNemar p = 0.0008). Anchors alone give 31.9%; adding cosine ranking changes 3 tasks; adding 1-hop neighbours changes 2. Harness mode returns nothing for 48 of 116 tasks (41.4%) because no issue identifier resolves to a node (`vm-main/results/a5/a5_summary.json`).

7. **H-A2 (gold unreachable statically but reachable dynamically) was not actually tested.** The summary reports 5 of 90 usable tasks with a gold node statically reachable from a fail-to-pass test (`a2_summary.json`, `tasks_gold_static_reachable`). But for 78 of the 90 tasks the fail-to-pass test function is new in `test_patch` and its module is not a node either, so the BFS had no source node and reachability is undefined, not false (`a2_tasks.csv`, column `f2p_source_levels`: `none` for 243 of 302 test entries). See section 4.1.

## 3. Step by step

### 3.1 A1 static census (`vm-main/results/a1/`)

Coverage of the inputs is complete: 129 tasks, 127 graphs, no missing graph or snapshot (`a1_summary.json`). The only edge type in any graph is `calls`, 452,588 edges in total.

Presence by kind, all files, all graphs: sync functions 287,841 of 289,266 (99.5%); classes 62,552 of 63,831 (98.0%); async 0; nested 0. The sync-function gap is entirely requests: 5,789 of 7,214 (80.3%) present, versus 100% in fastapi, rich and httpx (`omission_per_repo`). All 1,425 absent requests functions resolve by bare name to a test node (`misresolution_per_repo`). The result files do not say which functions these are. **[inferred]** Given the `src/` layout noted in the handoff, a path-to-module mismatch in the generator for part of the requests tree is the simplest explanation, but it has not been checked.

Issue text is a weak anchor. Of 1,014 extracted identifiers, 578 resolve to nothing, 5 exactly, 219 by suffix, 195 by substring; 121 land on test nodes and 86 on gold nodes (`identifier_tier_hist`). Structural distance d is defined for 47 of 129 tasks (36.4%); 54 tasks have zero resolvable anchors (`a5_summary.json`, `tasks_zero_anchors`). The review added a snapshot-based visibility measure because the graph-text version was confounded by the async omission (`scripts/REVIEW.md`); on it, 72 of 129 gold files rank in BM25's top 5 (`v_snap_file_rank_src_le5`).

### 3.2 A2 dynamic oracle (`vm-a2/results/a2/`, `a2_runs/`)

Run validity. All 129 tasks ran; run classes are clean 113, collection_error 9, no_tests 4 (all requests), import_error 2, killed 1 (rich_4006, no pre-fix trace even after the 60 s per-test rerun) (`a2_run_status.csv`, `README.md` section 4). "Usable" requires a clean run plus at least one confirmed fail-to-pass test: 90 of 129 (69.8%); fastapi 45 of 67, rich 38 of 48, requests 7 of 13, httpx 0 of 1 (`a2_summary.json`, `coverage`). Four rich tasks needed a rerun after the first attempt used up to about 36 GB and was killed (`README.md`).

Fail-to-pass confirmation is weaker than it looks. `FAIL_TO_PASS` is empty in `tasks.jsonl` for 124 tasks, so expected tests are the `def test_*` names added by `test_patch` (`a2_run_status.csv`, `f2p_expected_source`; `analyze.py` `expected_f2p`). Of 486 expected tests, 188 were confirmed fail-then-pass, 291 passed before the fix, 7 failed after it; only 55 tasks had every expected test confirmed (`a2_summary.json`, `f2p_check`). 23 clean runs are unusable because nothing flipped (`a2_run_status.csv`).

Recall. Pooled over usable tasks, any channel, all edges: representable recall 38.0%, agent-facing 30.3%. Non-test edges only: 37.2% and 32.3%. Edges incident to a gold node: 56.5% representable (585 of 1,036). Per task the mean representable recall is 53.9% (CI 49.4 to 58.5) (`usable_tasks`). Per repo (usable): fastapi 67.6% any / 74.6% direct; rich 30.3%; requests 38.7% (`per_repo_usable`). Miss causes: 70.9% are edges between two existing nodes that the graph simply lacks, 16.5% touch a nested function, 3.6% an absent async def, the rest an absent sync def (`miss_share_by_cause`). Every between-node miss has sub-cause `sync` (`a2_dyn_edges.jsonl`). Examples of missed non-test edges include `FastAPI.get` to `APIRouter.get`, `APIRouter.add_api_route` to `APIRoute`, `requests.api.request` to `Session.request`, and `Console._detect_color_system` to `Console.is_terminal` (`a2_dyn_edges.jsonl`). **[inferred]** These are ordinary method calls through `self` or a local, and class instantiations, which suggests the generator resolves few attribute calls.

Precision. Of 36,268 static edges whose two endpoints both executed, 7,664 were observed as calls (21.1%). The 37,768 unconfirmed edges are overwhelmingly between non-test nodes (fastapi 17,220 of 17,657) (`a2_static_unconfirmed.jsonl`). This is a lower bound: both endpoints running does not mean the call site ran, and tests covered only 16.4% of non-test nodes (`nontest_node_coverage`). Even so, a 21% confirmation rate inside executed code is far from PyCG-class precision, and the handoff's own census (fastapi graphs with more nodes than edges, requests `Session` in-degree 77) fits a name-matching generator better than a resolving one. **[inferred]** The generator looks name-based; a direct check of a few unconfirmed edges against source would settle it.

Gold functions. On usable tasks, 70 of 90 (77.8%) had a gold node executed by a confirmed fail-to-pass test. 4 of 90 (4.4%) had a gold function that is absent from the graph yet was executed, the case the graph cannot represent; across all 124 analysed tasks it is 9 (7.3%), 7 of them fastapi (10.4% of fastapi tasks). Status counts over all analysed gold symbols: in graph and executed 134, in graph not executed 325, absent and executed 18, absent not executed 46, new symbol executed post-fix 71, new symbol not executed 112 (`gold_status_counts`).

### 3.3 A3 encoder audit (`vm-a2/results/a3/`, `a3_gemma2/`)

Vector facts, 10 graphs: 256 dimensions, one vector per node and no extras; not unit-normed (mean norm 4.47 to 5.43); strongly anisotropic, with mean cosine to the mean vector 0.87 to 0.95, first principal component explaining 44% (fastapi) to 75% (httpx) of variance, and mean pairwise cosine 0.75 to 0.91 (`a3_vectors_stats.csv`). Top-1 neighbour cosine averages 0.999 in every repo (`a4_knn.csv`), so the usable dynamic range of `search_similar_code` scores is narrow.

Identification: embeddinggemma-300m, embeddinggemma-2 and all-MiniLM-L6-v2 were run over text, name, id and name+text, with no prompt and the documented prompts, truncated to 256-d. Best mean cosines 0.073, 0.015 and 0.036; pairwise Spearman at most 0.16 (`a3_per_model.csv`). The threshold for "identified" was 0.99. **[inferred]** The non-unit norms and anisotropy are consistent with un-normalised pooled hidden states from some model, but nothing in the files says which. Sampling note: the 200 nodes per graph are the first 200 keys with non-empty text, not a random sample (`scripts/planA/a3_encoder.py` line 132); this does not change the conclusion but should be stated.

### 3.4 A4 similarity probe (`vm-main/results/a4/`)

AUROC of cosine for relation-vs-random pairs, mean over 127 graphs: calls 0.898, containment 0.903, gold co-change 0.806 (51 graphs), same module 0.682, name overlap 0.675 (`a4_summary.json`). Per repo, calls AUROC is 0.933 in fastapi, 0.898 in requests, 0.848 in rich; gold co-change ranges from 0.20 to 1.00 across graphs (`a4_relations.csv`). So similarity does track call adjacency and containment above chance. But the top-10 neighbourhoods tell the agent-facing story: call neighbours 2 to 6%, same-module 9.7% (fastapi) to 49.3% (requests), test nodes 45 to 67% (`a4_knn.csv`). A `search_similar_code` call in fastapi returns mostly tests. **[inferred]** The 0.999 top-1 cosines are near-duplicate test and `docs_src` tutorial bodies.

### 3.5 A5 retrieval modes (`vm-main/results/a5/`)

Over the 116 tasks with a gold node in the graph (13 tasks are unhittable by any graph mode): gold-node Hit@10 is 25.9% anchors only, 26.7% harness, 26.7% harness plus 1-hop, 32.8% BM25; gold-file Hit@5 is 31.9%, 34.5%, 36.2%, 51.7%. BM25 beats harness significantly on file Hit@5 (p = 0.0008) but not on node Hit@10 (15 vs 8 discordant, p = 0.21). Per repo, the file gap is largest in fastapi (25.0% vs 50.0%, p = 0.0026) and absent in rich (34.9% vs 39.5%, p = 0.73) (`a5_summary.json`). Mode (c), free-text embedding of the issue, was not run because A3 identified no encoder (`README.md` section 5).

### 3.6 A6 release artefacts (`vm-a2/results/a6/`)

127 typed graphs were built from source plus traces: node kinds module, class, async_function, function and provided_only; edge types contains, imports, inherits, calls_static, calls_dynamic, tests (`a6_summary.json`). A fastapi v2 graph averages 6,018 nodes against roughly 3,870 provided, with 965 async defs and 2,148 nodes the provided graph lacks; edges average contains 4,822, imports 2,605, inherits 391, calls_static 2,214, calls_dynamic 408 (`a6_summary.json`, repo means). `calls_dynamic` uses direct edges only (`scripts/REVIEW.md` note 6). `tests` and `calls_dynamic` counts swing widely between commits of the same repo, 44 to 5,941 `tests` edges in rich; **[inferred]** from `a6_release.py`, each commit only receives edges from the tasks traced at that commit, so these two edge types are per-task samples, not repository properties.

Per-graph `provided_only` nodes (43 fastapi, 138 requests, 110 rich on average) are provided nodes that the v2 source parse did not find. The files do not explain them. This needs a look before the graph is released as "corrected".

Task profile cells for Plan B: d undefined 82; d=0 19; d=1 5; d of at least 2 23. The cell Plan B's H-B2 depends on, d of at least 2 with low visibility, holds 7 tasks, all fastapi (`task_profile.csv`, `a6_summary.json`).

## 4. Numbers that should not be quoted as they stand

Ranked by how much they would mislead a reader.

### 4.1 Static reachability (H-A2)

`analyze.py` maps each fail-to-pass pytest id to a node id, then walks up to the class and module until it finds a node; BFS starts from what it finds (`scripts/planA/a2/analyze.py` lines 330 to 345). The provided graph has no module nodes and the fail-to-pass tests are new functions from `test_patch`, so for 38 of 38 usable rich tasks and 40 of 45 fastapi tasks the walk ends at `none` and the source set is empty (`a2_tasks.csv`, `f2p_source_levels`). The reported "5 of 90 statically reachable" and "65 of 90 executed but not statically reachable" (`a2_summary.json`) are therefore mostly "no source", and the five reachable tasks are exactly the requests tasks whose test class was a node. A fair test needs a source that exists at the base commit: for example, the repo functions the fail-to-pass test calls directly in the trace, or the existing tests in the same test module. The traces already hold the first option.

### 4.2 Precision

21.1% is a lower bound over 16% of the library, as the summary itself notes. State it as "within executed code, at most 1 in 5 static edges was exercised", not as "precision is 21%". A manual check of 30 to 50 unconfirmed non-test edges against source would turn the inference about name-matching into a result.

### 4.3 Fail-to-pass basis

Only 55 tasks had every expected test flip; 291 expected tests passed pre-fix. Some of that is the regex picking up helper or regression tests, some may be real. The paper should report "at least one confirmed fail-to-pass test" as the inclusion rule and the 55 strict tasks as a sensitivity set.

### 4.4 Retrieval hit rates

A5 excludes the 13 tasks with no gold node, so every graph-based mode is reported on favourable ground; the BM25 corpus is graph node text, so it is blind to async code too. Report rates over all 129 tasks alongside, with the unhittable tasks counted as misses for the graph modes.

### 4.5 Open data questions

The requests sync-function gap (19.7% absent) and the A6 `provided_only` nodes are both unexplained in the files. Either could be a path-mapping difference between the generator and `common.py`, which would make both the A1 presence rates for requests and part of the v2 graph slightly wrong.

### 4.6 Coverage limits

One httpx task, not usable; no httpx evidence. Three rich tasks have traces cut by the 60 s per-test timeout and rich_4006 has none (`README.md`). Four requests tasks ran no tests at all.

## 5. What the results support saying now

- The competition graph omits all async and nested functions, and this reaches 17% of tasks and 31% of fastapi tasks through their gold patches (A1).
- The harness resolver masks the omission: most queries for absent async code return a different, often test, node (A1).
- Within executed code the `calls` edges capture 38% of real calls between existing nodes, and at most 21% of static edges between executed nodes were exercised (A2, with the bounds above).
- The vectors are not EmbeddingGemma output under any tested variant; nearest neighbours are mostly tests; similarity tracks calls and containment above chance but weakly in practice (A3, A4).
- Symbol-resolve-then-cosine retrieval returns nothing for two tasks in five and finds the gold file half as often as BM25 in fastapi (A5).
